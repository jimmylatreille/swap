What is this?

A single-dependency page transition engine built on GSAP 3.13.0. It renders 80 unique full-viewport animations — each one a GPU-accelerated, bidirectionally-stable timeline that can be played, reversed, and killed at any point.

80 Transition Variants
4 Rendering Layers
0 Dependencies
GPU Accelerated (force3D)

Quick Start

Load the scripts and call createTransition with the stage container and an options object. The engine exposes itself as a browser global — no bundler or ES modules needed:

HTML
<script src="js/gsap.js"></script>
<script src="js/transitions/utils.js"></script>
<script src="js/transitions/create-transition.js"></script>
JavaScript
const { createTransition } = window.PageTransitions;

// 1. Create a controller for transition #12 (Scale Bloom)
const ctrl = createTransition(document.querySelector("#stage"), { id: 12 });

// 2. Play forward (covers screen → reveals new content)
ctrl.play();

// 3. Reverse (uncovers screen → returns to previous state)
ctrl.reverse();

// 4. Kill and clean up DOM nodes
ctrl.kill();

How it Works

Every transition follows the same 3-phase cycle:

  1. Cover: The transition layer(s) animate over the viewport, hiding the current content. This is the ideal moment to swap page DOM or route.
  2. Hold: The screen is fully covered. Content swap occurs invisibly. The text in this demo updates automatically during this phase.
  3. Reveal: The layer(s) exit the viewport, revealing the new content with a polished ease.

createTransition( container, options )

The factory function. Creates and returns a transition controller object.

Parameters

ParamTypeRequiredDescription
containerHTMLElementYesThe element that hosts the transition layers. Usually the full-screen preview stage.
options.idNumberNo (defaults to 1)Transition index from 1–80. Selects the animation variant.

Return Value

Returns an object with 3 methods:

MethodSignatureDescription
play()() → voidPlays the timeline forward from the current playhead position. Covers the screen.
reverse()() → voidPlays the timeline backward. Uncovers the screen. Safe to call at any time — even mid-play.
kill()() → voidKills the GSAP timeline and runs all cleanup callbacks to remove injected DOM nodes and reset all inline styles.

Interrupt Safety

Every transition is interrupt-safe. You can call reverse() mid-play and the animation will reverse smoothly from its current position. The engine uses GSAP's gsap.timeline() with a paused: true default, giving you full manual control of the playhead.

Interrupt Safe Example
const ctrl = createTransition(stage, { id: 5 });
ctrl.play();

// You can call reverse() at ANY point — even 50ms after play()
setTimeout(() => ctrl.reverse(), 500);

Memory Management

Transitions that generate dynamic DOM (e.g. stripe overlays for "Blind Expand") register cleanup callbacks. When you call kill(), or when createTransition() is called again for a new transition, all old DOM nodes are garbage-collected automatically. This prevents memory leaks during rapid navigation.

The Layer System

Each transition stage has 4 stacked rendering layers. Understanding them lets you customise colours and effects without touching the animation code.

Layer Classz-indexRoleCSS Variable
.layer-bgauto (DOM order)Base background. Always fills the stage. Most transitions animate the background image (scale, xPercent) behind this layer.--bg
.layer-accentauto (DOM order)A semi-transparent colour wash. Fades in via accentFade() to add colour depth and brand identity.--primary-color
.layer-overlay2Solid colour used by specific full-cover transitions (e.g. Panel slides). Hidden by default.--primary-color
.layer-mask5The primary clip-path animation layer. Most wipes and iris transitions animate clip-path on this element. Starts clipped to inset(0 100% 0 0) (hidden).--bg

Customising Layer Colours

All layer colours are driven by CSS custom properties in :root. Edit css/main.css to retheme the entire engine:

css/main.css
:root {
  --primary-color: #9CEC5B;  /* Accent / overlay colour  */
  --bg:            #141414;  /* Background & mask colour  */
  --accent:        #6b7dff;  /* UI accent (buttons, tags) */
  --accent-2:      #ff5f92;  /* Secondary UI accent       */
}

Dynamic Stripe DOM

Transitions that use stripe overlays (e.g. T08, T26, T28, T33…) call the internal makeStripes(container, count, color, direction) factory. This injects a flex wrapper + N child stripe divs directly into the stage container. All of these are registered in the cleanups[] array and are automatically removed when kill() is called.

ParamTypeDefaultDescription
containerHTMLElement—Parent to append the stripe wrapper into.
countNumber—Number of stripes to generate.
colorString#030409Background fill colour of each stripe.
directionString"row""row" for vertical stripes, "column" for horizontal stripes.

UI Controls

Select a Transition Button

The circular button on the right side of the screen opens the transition carousel overlay. It shows all 80 transitions as scrollable cards.

  • Click a card to select and immediately play that transition.
  • Click the same active card again to reverse the animation.
  • The overlay auto-closes after a selection.
  • Click the backdrop or press Escape to dismiss without selecting.

Transition Label (Bottom Left)

Displays the currently selected transition ID and name with two control buttons:

ButtonAction
PlayRe-triggers the selected transition forward from its current position.
ReversePlays the timeline backward from its current position. Interrupt-safe.

Fullscreen Button (Top Right)

The four-arrow button toggles the browser's native Fullscreen API for the entire document. This is ideal for presentations or demos. Press Escape to exit fullscreen.

Documentation Button (Bottom Right)

The rounded button with the file-stack icon (this dialog). Click it to open this documentation lightbox. Press Escape or click the backdrop to close.

Keyboard Shortcuts

KeyAction
EscapeCloses the carousel overlay, documentation panel, or exits fullscreen — in that priority order.

Content Swap Simulation

When the transition layer fully covers the screen, the engine automatically swaps the headline text to simulate a real-world page load. On play(), the text changes to a "new page" state. On reverse(), it reverts. This is handled by a GSAP tl.add() callback inside stdContent() in create-transition.js.
